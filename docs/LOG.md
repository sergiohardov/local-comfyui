# Журнал

Что сделано, какие решения приняты и почему. Новые записи сверху.

## 2026-10-29 — инструмент как сервис

**Сделано:**

- **API в пакете `local-comfyui`:** `/tool/generate` (цепочка из нескольких LoRA с весами, `count` до 16, seed до 2⁶⁴−1), `/tool/jobs/{id}`, `/tool/status` (состояние, шаг текущего задания, очередь, видеопамять через `nvidia-smi`), `/tool/loras` (список, скачивание, загрузка с проверкой формата safetensors и sha256, удаление). Граф генерации — `graph.py`, тот же, что в шаблонах.
- **Обучение через API:** `/tool/train` принимает zip и параметры; тренер — постоянный сервис с маленьким HTTP API во внутренней сети Docker. Перед обучением очередь должна быть пуста, ComfyUI выгружает модели (`POST /free`), middleware отвечает 423 на `POST /prompt` до конца обучения. Прогресс разбирается из вывода sd-scripts: шаг, loss, оставшееся время.
- **Убрано:** `PROJECT_DIR`, `project.yaml` и проверка при старте (`start.py`), `template/`, `run.py`. Всё на Windows — в `data/`: модели и библиотека LoRA в `data/models`, `input`, `output`, `user`, `jobs`. Локально демо-LoRA переехали в библиотеку как `demo/...`.
- **Проверено:** картинка из интерфейса (64-битный seed, LoRA) повторяется через API пиксель в пиксель — и до, и после переезда библиотеки; две LoRA в одной генерации; статус во время генерации показывает шаг 6/28 и очередь; LoRA скачивается с тем же sha256, загружается обратно, повтор — 409, с `overwrite` — замена, удаление убирает и пустую папку проекта; плохие запросы отклоняются со всеми причинами сразу. Обучение через API: 200 шагов за 9 минут, версии `-v1`, `-v2`, `-v3` по порядку, промежуточные сохранения в библиотеке, генерация с новой LoRA сразу после; во время обучения генерация из API получает 423, повторное обучение — 409, кнопка Run в интерфейсе показывает «идёт обучение LoRA demo/apistyle-v3, генерация недоступна»; обучение при непустой очереди — 409; zip без подписи, не zip, неверные параметры — 400.

**Найдено:**

- **Тренер медленно отвечает, пока sd-scripts грузит модель** — до нескольких секунд. С таймаутом 3 с прослойка сочла его недоступным, и блокировка на это время снималась бы. Теперь отказ в соединении значит «тренера нет», а медленный ответ — «состояние прежнее»: обучение не принимается за простой.
- **Полоса tqdm кеширования латентов** («20/20») сначала разбиралась как шаги обучения; учитываются только строки `steps:`.
- **`/free` у ComfyUI** выгружает модели не только из видеопамяти, но и из оперативной: во время обучения ComfyUI держит 1,6 ГБ, тренер — до 12,5 ГБ из 15,5, которые отдаёт WSL.
- **Своя функция `comfy()` затёрла модуль `comfy`** внутри пакета — переименована в `call_comfy`.
- **Ответы JSON** отдаются в UTF-8 без `\u`-экранирования, иначе русские сообщения не прочитать в терминале.

**Решения** (обсуждены с пользователем):

- **Windows — сервис, Mac — клиент, как с платным API.** Пользователь хочет так: на Windows один раз склонировать, положить модели, поднять Docker; с Mac открывать визуальный интерфейс и по HTTP генерировать, обучать, получать и загружать LoRA, смотреть статус, комбинировать несколько LoRA. Без сетевых папок и без клиента в Docker на Mac. Это заменяет подключение папки проекта (шаг 2): обмен через коммит на Windows, переключение `PROJECT_DIR` и ручная остановка ComfyUI перед обучением оказались неудобны.
- **Сравнили с внешним ТЗ** (FastAPI-оркестратор `ai-manager`, клиентский SDK на Mac, профили, LoRA в Git LFS). Взяли из него профили как понятие (на стороне проекта), цепочку LoRA и автоматическую блокировку видеокарты. Не взяли: SDK на Mac, LoRA в LFS (бесплатная квота 1 ГБ, а LoRA ранга 16 весит 82 МБ), fp16 (у RTX 3080 есть bf16), Flux, одну перезаписываемую LoRA на профиль (без версий и промежуточных сохранений не выбрать точку обучения), синхронную отдачу PNG.
- **API — прослойка-пакет внутри ComfyUI, на том же порту 8188.** Проверено прототипом: пакет добавляет свои маршруты (они дублируются с префиксом `/api`) и middleware, который на время обучения отвечает на `POST /prompt` кодом 423 — и в API, и в интерфейсе (красная плашка с сообщением). Отдельный сервис-шлюз без прокси интерфейс бы не блокировал, а прокси для интерфейса — статика, вебсокет, проверка Origin у ComfyUI — лишняя движущаяся часть. С ComfyUI прослойка говорит через его обычный HTTP API; из внутренностей — только места подключения расширений, их перепроверяем при обновлении ComfyUI.
- **Библиотека LoRA на Windows** в `models/loras`, имена `проект/имя-vN`, все видны в интерфейсе; проект хранит копии у себя.
- **Генерация во время обучения отклоняется**, а не ждёт в очереди.
- **Референсы для обучения — zip** с картинками и `.txt`-подписями того же имени.
- **Без авторизации**, только домашняя сеть.

## 2026-10-29 — обучение LoRA

**Сделано:**

- **Образ `docker/trainer`:** kohya sd-scripts v0.12.3, Python 3.10, PyTorch 2.8.0+cu128; `bitsandbytes==0.50.2` и `numpy==2.2.6` закреплены здесь, в `requirements.txt` sd-scripts они без версий. Токенизаторы CLIP запечены в образ, обучение идёт офлайн.
- **Сервис `trainer`** с профилем `train`, запуск `docker compose run --rm trainer training/<имя>.yaml`. Модели только на чтение, проект только на чтение, кроме `loras/` и `output/`.
- **`train.py`:** проверяет файл обучения, подписи к каждой картинке, что база объявлена в `project.yaml` и лежит на месте, свободную видеопамять; собирает команду sd-scripts с настройками под 10 ГБ; кладёт итог в `loras/<имя>-v<N>.safetensors`, промежуточные — в `loras/<имя>-v<N>/`, копию конфига и набора — в `output/training/<имя>-v<N>/`; печатает sha256 и запись для `project.yaml`.
- **LoRA в генерации:** поля `lora` и `lora_strength` в `run.py` (`lora: null` у пункта выключает), шаблон `txt2img-lora`.
- **Заготовка:** `training/style.yaml`, `dataset/style/`.
- **Проверено:** набор из 20 картинок в стиле укиё-э (сгенерирован `run.py`, подписи `lcstyle, <что на картинке>` без слов о стиле), 600 шагов за 13 мин, 1,3 с/шаг, 8,2 ГБ видеопамяти. Сравнение через `run.py` с одним seed: без LoRA промпт `lcstyle, a lighthouse on a rocky shore` дал карандашный набросок, с LoRA — гравюру с плоскими цветами и контуром уже на шаге 200; к шагу 600 появились рамки и «печати» из эталонов — начало переобучения, ради такого выбора и нужны промежуточные сохранения. Старт ComfyUI сверяет sha256 LoRA, `txt2img-lora` из интерфейса генерирует с ней. Ошибки файла обучения, нет подписи, база не объявлена, занятая видеопамять — тренер не запускается и называет причину.

**Решения** (обсуждены с пользователем):

- **sd-scripts, а не OneTrainer.** sd-scripts — командная строка и TOML, который пишется руками, прямо сказано «8GB (10GB recommended)» для LoRA SDXL, Apache-2.0. У OneTrainer CLI держится на JSON, экспортированном из GUI, релизов нет, AGPL-3.0.
- **Отдельный образ:** sd-scripts проверен на Python 3.10 и PyTorch 2.6–2.8, у ComfyUI 3.13 и 2.14.
- **ComfyUI на время обучения останавливается вручную**, а тренер проверяет, что видеопамять свободна: если просить ComfyUI выгрузить модели, генерация с Mac посреди обучения снова их загрузит.
- **Проект задаёт, что обучать** (`training/<имя>.yaml`: база, шаги, ранг, learning rate, разрешение, повторы), **инструмент — как уместить в 10 ГБ** (только U-Net, кеши энкодеров и латентов, gradient checkpointing, bf16, AdamW8bit). Сменится машина — файлы проектов не меняются.
- **Подписи руками;** автоподписи отложены в ROADMAP.
- **Промежуточные сохранения в `loras/`, а не в `output/`:** ComfyUI видит LoRA только там, а без этого их не сравнить через `run.py`. `loras/` в `.gitignore`.
- **Примеров sd-scripts по ходу обучения нет.** Договорились попробовать и оставить, если поместятся в 10 ГБ. Первый раунд (шаг 200) прошёл, после второго (шаг 400) видеопамять дошла до 9,9 ГБ из 10, оперативная — до 12,4 из 15,5, и обучение встало: семь минут без единого шага. Под WSL драйвер в таком случае не падает с ошибкой, а уходит в общую память и замедляется в разы. Выбор точки — через `run.py` на настоящем ComfyUI.

**Найдено:**

- **`torch.cuda.mem_get_info` под WSL не видит чужую видеопамять:** при работающем ComfyUI показывал 8,86 ГБ свободными, `nvidia-smi` — 2,75. Тренер проверяет через `nvidia-smi`, он есть в контейнере.
- **`accelerate config` при сборке образа выбирает CPU:** видеокарты при сборке нет. Первое обучение пошло на процессоре; теперь настройки передаются `accelerate launch` флагами при запуске.
- **PyTorch с `--index-url` индекса PyTorch не ставится:** зависимости нужен `flit_core` с PyPI. PyPI подключён дополнительным индексом, а PyTorch закреплён версией `+cu128`, которая есть только в индексе PyTorch.
- **Сборка образа во время генерации** упирается в 16 ГБ памяти WSL: одна картинка шла 12 минут вместо 13 секунд. Записано в README.

## 2026-10-28 — текст → картинка

**Сделано:**

- **Типовой граф `txt2img`** (SDXL без LoRA) в своём пакете `custom_nodes/local-comfyui` — без узлов, только `example_workflows/`. В интерфейсе он в Workflow → Browse Templates, раздел local-comfyui.
- **Пакетный прогон `run.py`:** список промптов из `prompts/` проекта, общие настройки с переопределением в пунктах, по заданию на seed, seed в имени файла `output/<список>/<пункт>-s<seed>_00001_.png`. Ошибки списка называются все сразу до генерации; отказ ComfyUI передаётся его словами.
- **`style` в `project.yaml`:** `prompt` и `negative` дописываются к каждому пункту прогона; `start.py` проверяет поле.
- **Заготовка:** `prompts/example.yaml` и пустой `style`.
- **Проверено:** шаблон открывается из Browse Templates и генерирует в `output/` проекта; прогон примера — 3 картинки за 49 с; повтор seed 1000 даёт картинку, совпадающую с первой до пикселя; список с девятью видами ошибок, неизвестная модель, путь за пределы проекта и неизвестный сэмплер отклоняются с понятным сообщением; неверный `style` не даёт контейнеру стартовать.

**Решения** (обсуждены с пользователем):

- **Типовые графы — пакетом расширения в образе.** ComfyUI v0.42.1 показывает в Browse Templates только `custom_nodes/<пакет>/example_workflows/`. Копии в заготовке проекта не получали бы исправлений, а подключение папки инструмента внутрь `workflows/` проекта оставило бы в нём служебную папку. Пакет свой и без узлов, так что решение «сторонние расширения не ставим» в силе.
- **Пакетный прогон из git.** Эталонов нужно 20–30, кандидатов — сотни; список промптов и seed в репозитории проекта позволяют повторить любую картинку. Ради этого и выбирали ComfyUI, а шагам спрайтов и иконок нужен тот же механизм.
- **По заданию на seed, а не batch size:** картинку из пачки ComfyUI одним seed не повторить.
- **`checkpoint` в списке обязателен:** если умолчание инструмента сменится, картинки проекта не должны поменяться молча.
- **LoRA в `txt2img` пока нет:** её ещё не на чем проверить. Добавим на шаге обучения LoRA.

**Найдено:**

- **Правка `project.yaml` требует `docker compose restart`:** `up -d` пересоздаёт контейнер только при изменении `.env` или `compose.yaml`. Записано в README.
- **В Git Bash** путь `/opt/tool/run.py` в `docker compose exec` превращается в путь Windows; в PowerShell такого нет. В Git Bash помогает `MSYS_NO_PATHCONV=1`.

## 2026-10-28 — подключение проекта

**Сделано:**

- **`MODELS_DIR` и `PROJECT_DIR` вместо `DATA_DIR`.** Общие базовые модели — в `MODELS_DIR` (по умолчанию `data/models`). Папка проекта подключается целиком: `input/`, `output/`, `loras/` (поверх `models/loras`) и `workflows/` (сохранённые workflow интерфейса). Без `PROJECT_DIR` подключается песочница `data/sandbox`. Старые `data/input` и `data/output` перенесены в неё.
- **Проверка при старте** (`docker/comfyui/start.py`, Python внутри контейнера): формат и имя проекта, лишние поля, наличие и sha256 базовых моделей и LoRA. При ошибке ComfyUI не запускается, а в логе — список проблем и что делать. Хеши кешируются в `data/cache` по размеру и дате файла: SDXL и ControlNet хешируются около минуты, старт с кешем — около 9 с.
- **Заготовка `template/`:** `project.yaml`, `.gitignore` (`loras/`, `output/`), `.gitattributes` (картинки через LFS), пустые `input/`, `dataset/`, `workflows/`.
- **sha256 моделей** добавлены в таблицу README: их пишут в `project.yaml`.
- **Проверено:** песочница стартует без проверки; проект с неизвестным полем, неверным именем, чужим sha256, отсутствующей моделью, путём за пределы папки, хешем без кавычек, отсутствующей и чужой LoRA не стартует, и каждая ошибка названа; исправный проект стартует, ComfyUI видит только его LoRA, сохранённый граф ложится в его `workflows/`, пробная генерация — в его `output/`.

**Решения** (обсуждены с пользователем):

- **Проект подключается папкой на Windows, а не отправляет задания по сети.** Сравнивали два варианта. Сервис по сети: Mac шлёт задание шлюзу, Windows ничего не хранит. Но API ComfyUI v0.42.1 принимает только картинки (`/upload/image`, `/upload/mask`), не умеет загружать LoRA и удалять файлы, а историю и очередь показывает всем клиентам, так что понадобились бы свой шлюз, клиент на Mac и кеш LoRA. Подключение папки почти не требует кода и даёт самую строгую изоляцию: ComfyUI видит только подключённый проект. Цена — один проект за раз и обмен результатами через git (коммит на Windows, `pull` на Mac). Интерфейс ComfyUI с Mac по сети работает и так. Сервис по сети отложен в конец ROADMAP; структура папки проекта у обоих вариантов одна, так что его можно надстроить, не переделывая проекты. Бывший шаг 3 «Клиент для Mac» снят, номера следующих шагов сдвинулись.
- **Проект хранит всё своё:** входы и датасет — в git через LFS, LoRA — в GitHub Releases (в LFS бесплатная квота 1 ГБ, а версии LoRA по 50–200 МБ копятся), черновики `output/` — не в git, отобранное переносится в ассеты проекта.
- **В `project.yaml` только то, что уже читается:** базовые модели и LoRA. Поля без кода, который их читает, никто не проверяет, и к моменту использования они разойдутся с нужными.
- **Ошибка при старте, а не при генерации.** Нет модели или LoRA, или это другая версия — контейнер не запускается и говорит, что не так. Модели по-прежнему ставятся руками на Windows; LoRA приватного репозитория качается вручную из браузера, токен GitHub на машине не держим. Автоматизируем, если начнёт мешать.
- **sha256 в YAML — в кавычках:** хеш из одних цифр YAML прочитал бы как число; проверка требует строку и подсказывает про кавычки.

## 2026-10-28 — ComfyUI в Docker, отдельный инструмент

**Сделано:**

- **Сервис `comfyui`** в `compose.yaml`: ComfyUI v0.42.1, PyTorch 2.14.1 с CUDA 13.0, Python 3.13, видеокарта через `deploy.resources.reservations.devices`. Модели, входы, результаты и workflow лежат в `DATA_DIR` на хосте и переживают пересборку.
- **Перенесено из Lootlords** (ветка `feature/art-comfyui`, в `main` игры не мерджилась): Dockerfile, сервис, подготовка Windows и раздел про модели. Переменная `ART_DATA` переименована в `DATA_DIR`, профиль `art` убран: здесь сервис единственный.
- **Папки по проектам проверены:** LoRA из `models/loras/<проект>/` видны в списке узла, префикс `<проект>/` в Save Image пишет в `output/<проект>/`, Load Image принимает путь из подпапки `input/`, но в списке интерфейса её не показывает.
- **Пробная генерация** на RTX 3080: SDXL base, 1024×1024, 28 шагов, `dpmpp_2m`/`karras` — первая после запуска около 30 с, следующие около 10 с, 3,3 шага в секунду. Шаблон «SDXL Simple» из интерфейса тоже проходит.

**Решения** (обсуждены с пользователем):

- **Отдельный репозиторий, а не сервис в игре.** Другая машина (Windows с NVIDIA против любой, где разрабатывают игру), другие зависимости (образ на 10 ГБ с CUDA, который не нужен ни CI игры, ни разработке на Mac) и другой ритм изменений. С игрой связь одна — готовые картинки по её контракту.
- **Инструмент общий, данные — у проекта.** Стиль, промпты, эталоны, позы и LoRA одной игры не подходят другой, поэтому в репозитории инструмента их нет: исходники хранятся в репозитории проекта (у Lootlords — `art/`), а на диске Windows — подпапки `<проект>/` в `loras`, `input`, `output`. Базовые модели общие, чтобы не дублировать гигабайты.
- **Генерация на своей Windows-машине** (i3-12100F, 32 ГБ, RTX 3080 10 ГБ), а не на Mac и не в облаке. M1 Pro на 16 ГБ для Flux и обучения LoRA слишком медленный, а Docker на macOS видеокарту не видит.
- **Проекты разрабатываются на Mac, инструмент работает на Windows.** С Mac доступны интерфейс и API ComfyUI по сети, позже — клиент инструмента. Сам инструмент дорабатываем на Windows-машине: проверить генерацию можно только там, где есть видеокарта.
- **ROADMAP собран из планов Lootlords:** LoRA, спрайты по одному скелету, постобработка с `rembg`, иконки с рамкой, оверлеи по точкам крепления. Сначала доводим инструмент по этому списку, потом возвращаемся к играм и дополняем его по надобности. Всё проектное инструмент берёт из папки проекта.
- **База — SDXL.** Генерация и обучение LoRA помещаются в 10 ГБ, лицензия разрешает коммерческое использование. Flux на 10 ГБ только генерирует, и медленно, а FluxGym требует для LoRA минимум 12 ГБ.
- **ComfyUI в Docker, а не portable-сборка.** Smart App Control в Windows 11 блокирует неподписанные `.dll` и `.pyd` из Python-пакетов, portable-сборка не запустилась. Выключать защиту пользователь не захотел, а Linux внутри Docker она не трогает.
- **ComfyUI, а не A1111, Forge, InvokeAI или Fooocus.** Граф workflow отправляется по HTTP API в виде JSON, его можно хранить в git и прогонять пачкой; новые модели и техники появляются в ComfyUI раньше других. Для ручной доработки позже можно подключить Krita AI Diffusion к этому же серверу.
- **Версии закреплены:** ComfyUI на релизе старше недели, PyTorch по рекомендации README ComfyUI (CUDA 13.0 нужна для серий 20 и новее). Обновляем вместе.
- **Расширения в образ не ставим:** скелет позы готовим сами, препроцессоры OpenPose не нужны.
- **Docker Desktop — с docker.com, а не из Microsoft Store.** Ошибка `docker-credential-desktop: executable file not found` оказалась не про Store: в системном `PATH` была запись `C:\Program Files\WireGuard"` с лишней кавычкой, и Go на Windows сливал после неё все папки в одну. Рецепт — в README.

**Найдено при запуске:**

- **«Missing models» в шаблоне** было из-за трёх причин сразу: `.env` указывал на папку по умолчанию, контейнер не пересоздали после правки `.env`, а шаблон «SDXL Simple» ждёт ещё и refiner. В README — что проверить и что выбрать в узле.
- **WSL 2 отдаёт контейнерам половину RAM:** ComfyUI видит 15,9 ГБ из 32. Для генерации хватает; для обучения лимит поднимается через `.wslconfig`.
