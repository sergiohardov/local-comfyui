## 2026-10-29 — снаряжение по слотам

**Сделано:**

- **`init.slot`:** `armor`, `helmet`, `right_hand`, `left_hand`. Инструмент строит зону слота по скелету (`parts.slot_zone`) и генерирует на картинке базы только в ней; `denoise` по умолчанию 1. Для шлема ControlNet получает позу без точек лица. В ответе — `zone_url`.
- **`post: parts` по слоту:** доспех — туловище и конечности, шлем — голова, оружие — новая часть `right_weapon` / `left_weapon` на кости предплечья, рисуется поверх руки. Оружие — пиксели фигуры в зоне, изменившиеся по сравнению с базой, с залитыми дырами. Дорисовка туловища под руками — только когда в результате есть туловище.
- **Порядок отрисовки** получил места для оружия после предплечий; у частей рук номера `order` сдвинулись.
- **Проверено:** база в рубахе и штанах, на ней по API — латы и кожаный доспех, закрытые топхельм и рогатый шлем, меч и топор в правой руке, у каждого только части своего слота. Через `/tool/animate` собраны и проанимированы пять наборов: база; латы, топхельм и меч; кожа, рогатый шлем и топор; верх лат со штанами базы, рогатый шлем и меч; кожа и топхельм. Шлемы садятся на шею базы, оружие в кулаке поворачивается с предплечьем, швов на шее, плечах и бёдрах нет. Ошибки: слот без позы, неизвестный слот, шлем без ушей в позе — 400.

**Решения:**

- **Зона слота — по скелету, а не по маске базы:** её можно построить сразу при постановке генерации, без лишнего прохода BiRefNet по базе; запас на объём доспеха задан в долях роста корпуса.
- **Оружие — по разнице с базой, без маски базы:** над фоном оружие отличается от фона, на руке — сжатый вокруг рукояти кулак тоже отличается, и он нужен в части: пальцы поверх рукояти.

**Найдено:**

- **Превью на холсте `rig`:** поднятый топор уходит за край кадра 512 — в игре холста нет, а для превью это ограничение.
- **Рогатый шлем** на базовой SDXL иногда выходит с «эльфийскими» ушами по бокам.

## 2026-10-29 — персонаж из частей

**Сделано:**

- **Модуль `parts.py`:** кости по точкам позы, разметка пикселей фигуры по частям, сборка частей на холсте, `rig`, превью анимации.
- **`post` с типом `parts`:** персонаж режется на 10 частей по костям. Пиксель достаётся части с ближайшей костью, внутри туловища руки забирают то, что лежит на них. Шея принадлежит туловищу, голова начинается от челюсти. Конечность — одна связная часть, оторванный кусок уходит к части, которой касается. Каждая конечность берёт диск вокруг сустава. Генерация ложится на холст `size` целиком, в одном масштабе, по оси бёдер; `ground` — нижняя точка силуэта.
- **Дорисовка под руками:** вторая генерация с тем же checkpoint, LoRA и промптом по картинке со стёртыми руками и маской того, что они закрывали. API ведёт задание в две стадии: после генерации — `running` со `stage`, потом части.
- **Кубик `init` с маской:** `SetLatentNoiseMask` в графе, перерисовывается только белое маски.
- **`/tool/post` с типом `parts`:** нарезка заново из картинки генерации или из картинки с прозрачностью.
- **`POST /tool/animate`:** GIF из частей по позам — углам костей, части можно брать из разных результатов одного скелета.
- **Проверено:** база в рубахе и штанах в позе с руками в стороны, сгенерированная сразу в части, — 10 частей, `rig` с 10 костями, `ground` 508,5 на холсте 512, стадия дорисовки видна в задании. Та же база через `/tool/post` по картинке генерации — те же кости и смещения частей. Персонаж в доспехе (генерация доспеха на этой базе из прототипа) через `/tool/post`, затем `/tool/animate` с доспехом и головой базы: 24 кадра 512×512, шеи и суставов без швов, бока под поднятой рукой — доспех. Ни в одной части нет оторванных кусков больше 4 px. Ошибки: нет позы, нет нужных точек, чужое поле, плохое тело `/tool/animate` — 400 со всеми причинами. Спрайт с позой, иконка через `/tool/post` и обычная генерация работают как раньше.

**Решения** (обсуждены с пользователем):

- **Персонаж из частей вместо оверлеев.** Ветка `feature/overlays` (тип `overlay`: предмет на сером манекене, слой поверх спрайта, перенос на другие телосложения по точкам крепления) работала, но предметы смотрелись наклеенными. Пользователь: в 2D-играх снаряжение органично вписано в телосложение. В таких играх предмет заменяет часть тела, нарисованную в нём, а не лежит поверх, и рисуется под каждое телосложение по слотам — число картинок растёт как сумма слотов, а не как их произведение. Персонажу нужна анимация и не должно быть видимых стыков — это персонаж из частей на костях. Ветку `feature/overlays` не мерджим.
- **Свой формат вместо Spine:** части и `rig` — то, что PixiJS собирает из вложенных `Container` с `pivot`; Spine требует платную лицензию на рантайм, а свои кости проще.
- **Снаряжение генерируется на настоящей базе,** не на манекене: модель видит тело, свет и стиль, и части сходятся без швов. В прототипе так проверены доспех (тело без головы, кистей и стоп), верх доспеха со штанами базы, меч (зона у кулака, кисть перерисована вокруг рукояти) и закрытые шлемы.
- **Холст частей — вся генерация,** без выравнивания по ступням: так ступни не обрезаются, а линия пола приходит в `rig.ground`. Холст спрайтов (шаг 9) не меняется.

**Найдено в прототипах:**

- **Базы под снаряжение** («bald head, empty hands» и негатив про шлемы, оружие и плащи) получаются с первого раза и сами по себе убирают большую часть эффекта наклейки.
- **Поза с руками у бёдер** путает нарезку: рука утаскивает подсумки пояса. Поза с руками в стороны — нет.
- **Плечо при подъёме руки выше ~60°** выглядит изломанным: наплечник частично остаётся на туловище. Для удара и получения урона углы меньше.
- **Шлем:** перерисовка головы целиком дала другого человека с рогами. Вырезка головы, увеличенная до 1024, — ещё хуже: новые лица поверх старых. Помогло убрать из позы точки лица: ControlNet перестаёт требовать лицо, и закрытые шлемы выходят настоящими. Открытые шлемы с видимым лицом пока не получаются.
- **Доводка наклеенного предмета img2img** (`denoise` 0,3–0,45 по базе с предметом) даёт тонкую разницу, а при 0,45 уже меняет сам предмет — отказались.
- **Высота стопы** у человека и дварфа разная (0,2 и около 0,3 расстояния шея–бёдра) — линию пола надёжнее мерить по силуэту, чем считать из скелета.
- **Тонкая полупрозрачная перемычка** связывает оторванный кусок с конечностью на полном размере и пропадает на холсте 512 — связность считается по плотным пикселям с небольшой эрозией.

## 2026-10-29 — иконки и рамки

**Сделано:**

- **`post` с типом:** `sprite` (по умолчанию, как было), `frame`, `icon`. Общие поля — `edges`, `palette`, `model`; результат — `<seed>_<тип>.png` и ссылка `sprite_url`, `frame_url` или `icon_url`.
- **Кубик `init` в `/tool/generate`** — генерация от исходной картинки (img2img): `LoadImage` + `VAEEncode` вместо пустого латента, KSampler с `denoise` меньше 1.
- **`frame`:** инструмент рисует заготовку — кольцо вокруг окна на тёмном поле, нейтрально-серое, чтобы цвета задавали промпт и LoRA, — и генерирует от неё с `denoise` 0,9. Снаружи прозрачность по маске BiRefNet, окно вырезается по прямоугольнику; рамка обрезается в квадрат вокруг окна и масштабируется до `size`, в ответе — `window` в пикселях рамки.
- **`icon`:** предмет без фона вписывается в окно с отступом `margin` и по центру; под ним цвет окна `background`, поверх рамка, тонированная `tint` по яркости (`ImageOps.colorize` с цветом в середине).
- **`/tool/post`** принимает все три типа.
- **Проверено:** четыре рамки из одной заготовки — разный орнамент, окно на месте, снаружи и внутри прозрачно. Пять иконок в одной рамке по редкостям Lootlords (gray, green, blue, epic, legendary): меч, зелье, шлем, кольцо, амулет — рамка перекрашена цветом редкости, окно своего цвета, предмет вписан и по центру. Иконка и рамка через `/tool/post`, вариация меча через `init` с `denoise` 0,5. Ошибки: рамка без окна, не base64, окно за пределами, `tint` не цвет, `margin` < 0, `denoise` вне диапазона, неизвестный тип, поле чужого типа — 400 со всеми причинами. Старый `post` без `type` даёт спрайт, обычная генерация не изменилась.

**Решения** (обсуждены с пользователем):

- **Рамка генерируется, потом накладывается** — так решил пользователь, а не рамка от проекта. Чтобы окно было предсказуемым, инструмент сам задаёт раскладку и генерирует от неё.
- **Одна рамка на все редкости**, редкость — цветом окна и тонировкой рамки; пять разных рамок в едином стиле выдержать сложнее.
- **Рамка приходит в каждом запросе** в base64, в инструменте не хранится: это десятки килобайт.
- **Предмет вписывается в окно целиком** — у иконок, в отличие от спрайтов, каждый предмет должен одинаково заполнять окно.
- **Атлас не делаем:** отдельные PNG; «сетка иконок» стайлгайда — это размер, окно и отступ, а упаковку в атлас лучше делает сборка игры под свой движок.
- **Один метод `/tool/generate`, сценарии — наборы параметров.** Персонаж, иконка, рамка, позже оверлей и локация собираются из одних кубиков: промпт и LoRA, поза, исходная картинка, обработка результата. Метод на каждый сценарий дублировал бы генерацию, очередь, задания и проверки и не давал бы непредусмотренных сочетаний. Чтобы один метод не стал свалкой полей, обработка — одно поле с типом; новый сценарий — новый тип, не новый метод. Готовые наборы — в репозитории проекта.

**Найдено:**

- **BiRefNet не вынимает окно рамки:** в трёх из четырёх сгенерированных рамок он счёл заполненную середину частью рамки — модель рисует там тёмную панель.
- **Заливка от центра** по сходству с центральным пикселем останавливается кругом на радиальном освещении панели, а заливка до первой границы утекает через щели орнамента или застревает в фактуре.
- **Ключ по цвету не работает:** на просьбу «сплошной пурпурный центр и фон» SDXL красит пурпурным всё, включая рамку, и с градиентами.
- **Генерация от заготовки** при `denoise` 0,6–0,75 почти не меняет кольцо, при 0,9 даёт богатый орнамент и сохраняет окно — это значение по умолчанию.

## 2026-10-29 — постобработка

**Сделано:**

- **Удаление фона — встроенное в ComfyUI v0.42.1:** узлы `LoadBackgroundRemovalModel` и `RemoveBackground` на BiRefNet, модель `background_removal/birefnet.safetensors` (444 473 596 байт, MIT) из `Comfy-Org/BiRefNet` — оттуда её берёт и шаблон самого ComfyUI.
- **Поле `post` в `/tool/generate`:** граф после VAEDecode снимает маску переднего плана и сохраняет её картинкой; когда задание готово, `post.py` собирает спрайт — фигура на квадратном прозрачном холсте, жёсткие края и палитра по желанию — и кладёт его в `output/api/<job_id>/<seed>_sprite.png`. Сборка идёт в отдельном потоке и один раз, дальше берётся готовый результат.
- **`POST /tool/post`:** спрайт из любой картинки; с прозрачностью — сразу по её альфе, без — через BiRefNet в ComfyUI.
- **Шаблон `sprite`:** поза, LoRA и удаление фона, на выходе PNG с прозрачностью.
- **Проверено:** рыцарь с мечом, волшебник, гоблин и робот в одной позе с `post: {"size": 512}` — фон снят чисто, нижняя точка силуэта у всех ровно на 512, ось тела по центру (меч и плащ рыцаря уходят в стороны, тело не сдвигается), головы на одной высоте. Спрайт рыцаря через `/tool/post` с холстом 256, `hard` и палитрой из 8 цветов — ровно 8 цветов, альфа только 0 и 255. Обрезка даёт предупреждение («обрезано сверху 166 px»). Шаблон `sprite` из интерфейса даёт RGBA, 80% холста прозрачно. Ошибки полей `post` — 400.

**Решения** (обсуждены с пользователем):

- **BiRefNet из ComfyUI, а не `rembg`.** У `rembg` модели в ONNX, правило «модели только `.safetensors`» их не пропускает, и он тянет свои зависимости; встроенный узел работает с safetensors и ничего не добавляет в образ.
- **Один масштаб для всех спрайтов** — холст делить на высоту генерации, а не «вписать каждый силуэт»: иначе маленький персонаж раздувается, а персонаж с поднятым оружием съёживается, и пропорции, заданные позой, теряются.
- **Ноги у нижнего края, по центру — ось тела.** Точка привязки спрайта у ступней — обычная для 2D: игра ставит спрайт на линию пола одной координатой. Центр по середине бёдер из позы, чтобы оружие и плащ не сдвигали тело; `padding` оставляет место под тень, если понадобится.
- **Палитра — после масштабирования, без дизеринга:** иначе ресемплинг добавил бы промежуточные цвета, а дизеринг испортил бы плоскую комиксную заливку. Масштаб — с премультиплицированной альфой, чтобы мягкая кромка не набрала цвет фона.
- **`post` и в генерации, и отдельным `/tool/post`:** поменять холст или палитру без новой генерации.
- **В интерфейсе — только удаление фона:** выкладку на холст по оси тела и палитру встроенными узлами не собрать, а сторонние расширения не ставим.

**Найдено:**

- **`JoinImageWithAlpha` инвертирует маску** (прозрачно там, где 1), а `RemoveBackground` даёт 1 на фигуре — в шаблоне между ними `InvertMask`.
- **Спрайт из генерации и тот же спрайт через `/tool/post` по сохранённой картинке** совпадают внутри фигуры (разница цвета ≤ 1), но расходятся в 182 пикселях мягкой кромки из 262 тысяч: в генерации BiRefNet видит картинку прямо из VAE, с плавающей точкой, а в `/tool/post` — 8-битный PNG.

## 2026-10-29 — спрайт по скелету

**Сделано:**

- **Поле `pose` в `/tool/generate`:** 18 именованных точек OpenPose в пикселях холста, сила, начало и конец действия, модель ControlNet. Инструмент рисует скелет (`pose.py`) и кладёт его в `input/api/<job_id>/pose.png`, граф вставляет `ControlNetLoader` + `LoadImage` + `ControlNetApplyAdvanced` между промптами и KSampler. В ответе — `pose_url` на скелет.
- **`POST /tool/pose`** — только картинка скелета, для правки позы и для интерфейса.
- **Шаблон `txt2img-pose`** — LoRA и ControlNet позы, скелет загружается в LoadImage; связи всех трёх шаблонов сверены программно.
- **Уборка `data/`** по просьбе пользователя: в Корзину ушли результаты, загрузки, записи обучений и остатки старой структуры демо-проекта; остались базовые модели, обученные LoRA `demo/*`, их 20 референсов в `data/demo/dataset/style` и настройки интерфейса.
- **Проверено:** нейтральная поза «стоит прямо, руки чуть в стороны, ступни у нижнего края» на 1024×1024 — рыцарь, волшебник, гоблин и робот, каждый без LoRA и с `demo/style-v1` на 0,8, один seed: у всех восьми голова, плечи, кисти и ступни на точках скелета, ноги на одной линии; даже гоблин вытянут в пропорции скелета. Превью из `/tool/pose` совпадает байт в байт со скелетом генерации. Шаблон `txt2img-pose` из интерфейса генерирует в позе. Неизвестная точка, точка вне холста, не пара чисел, сила вне 0–2, `start ≥ end`, нет такой ControlNet — 400 со всеми причинами.

**Решения** (обсуждены с пользователем):

- **Проект присылает точки, а не картинку.** Толщину линий держит инструмент: ControlNet от xinsir учили на толстых, и проектам не нужно об этом знать. Поза и будущие точки крепления снаряжения — одни и те же числа, правка позы — правка чисел.
- **Поза — поле `/tool/generate`, а не отдельный эндпоинт:** ещё одна «насадка» к генерации, как LoRA; seed, `count` и LoRA работают так же.
- **Поза приходит в каждом запросе,** в инструменте не хранится: это несколько килобайт JSON, место ей — в репозитории проекта.
- **Толщина линий — 1/64 большей стороны холста** (16 px на 1024), конечности — эллипсы на 60% яркости, суставы — точки полного цвета, как в эталонной отрисовке OpenPose.

## 2026-10-29 — инструмент как сервис

**Сделано:**

Перед обучением очередь должна быть пуста, ComfyUI выгружает модели (`POST /free`), middleware отвечает 423 на `POST /prompt` до конца обучения. Прогресс разбирается из вывода sd-scripts: шаг, loss, оставшееся время.
- **Убрано:** `PROJECT_DIR`, `project.yaml` и проверка при старте (`start.py`), `template/`, `run.py`. Всё на Windows — в `data/`: модели и библиотека LoRA в `data/models`, `input`, `output`, `user`, `jobs`. Локально демо-LoRA переехали в библиотеку как `demo/...`.
- **Проверено:** картинка из интерфейса (64-битный seed, LoRA) повторяется через API пиксель в пиксель — и до, и после переезда библиотеки; две LoRA в одной генерации; статус во время генерации показывает шаг 6/28 и очередь; LoRA скачивается с тем же sha256, загружается обратно, повтор — 409, с `overwrite` — замена, удаление убирает и пустую папку проекта; плохие запросы отклоняются со всеми причинами сразу. Обучение через API: 200 шагов за 9 минут, версии `-v1`, `-v2`, `-v3` по порядку, промежуточные сохранения в библиотеке, генерация с новой LoRA сразу после; во время обучения генерация из API получает 423, повторное обучение — 409, кнопка Run в интерфейсе показывает «идёт обучение LoRA demo/apistyle-v3, генерация недоступна»; обучение при непустой очереди — 409; zip без подписи, не zip, неверные параметры — 400.

**Найдено:**

- **Тренер медленно отвечает, пока sd-scripts грузит модель** — до нескольких секунд. С таймаутом 3 с прослойка сочла его недоступным, и блокировка на это время снималась бы. Теперь отказ в соединении значит «тренера нет», а медленный ответ — «состояние прежнее»: обучение не принимается за простой.
- **Полоса tqdm кеширования латентов** («20/20») сначала разбиралась как шаги обучения; учитываются только строки `steps:`.
- **`/free` у ComfyUI** выгружает модели не только из видеопамяти, но и из оперативной: во время обучения ComfyUI держит 1,6 ГБ, тренер — до 12,5 ГБ из 15,5, которые отдаёт WSL.
- **Своя функция `comfy()` затёрла модуль `comfy`** внутри пакета — переименована в `call_comfy`.
- **Ответы JSON** отдаются в UTF-8 без `\u`-экранирования, иначе русские сообщения не прочитать в терминале.

**Решения** (обсуждены с пользователем):

- **Windows — сервис, Mac — клиент, как с платным API.** Пользователь хочет так: на Windows один раз склонировать, положить модели, поднять Docker; с Mac открывать визуальный интерфейс и по HTTP генерировать, обучать, получать и загружать LoRA, смотреть статус, комбинировать несколько LoRA. Без сетевых папок и без клиента в Docker на Mac. Это заменяет подключение папки проекта (шаг 2): обмен через коммит на Windows, переключение `PROJECT_DIR` и ручная остановка ComfyUI перед обучением оказались неудобны.
- **Сравнили с внешним ТЗ** (FastAPI-оркестратор `ai-manager`, клиентский SDK на Mac, профили, LoRA в Git LFS). Взяли из него профили как понятие (на стороне проекта), цепочку LoRA и автоматическую блокировку видеокарты. Не взяли: SDK на Mac, LoRA в LFS (бесплатная квота 1 ГБ, а LoRA ранга 16 весит 82 МБ), fp16 (у RTX 3080 есть bf16), Flux, одну перезаписываемую LoRA на профиль (без версий и промежуточных сохранений не выбрать точку обучения), синхронную отдачу PNG.
- **API — прослойка-пакет внутри ComfyUI, на том же порту 8188.** Проверено прототипом: пакет добавляет свои маршруты (они дублируются с префиксом `/api`) и middleware, который на время обучения отвечает на `POST /prompt` кодом 423 — и в API, и в интерфейсе (красная плашка с сообщением). Отдельный сервис-шлюз без прокси интерфейс бы не блокировал, а прокси для интерфейса — статика, вебсокет, проверка Origin у ComfyUI — лишняя движущаяся часть. С ComfyUI прослойка говорит через его обычный HTTP API; из внутренностей — только места подключения расширений, их перепроверяем при обновлении ComfyUI.
- **Библиотека LoRA на Windows** в `models/loras`, имена `проект/имя-vN`, все видны в интерфейсе; проект хранит копии у себя.
- **Генерация во время обучения отклоняется**, а не ждёт в очереди.
- **Референсы для обучения — zip** с картинками и `.txt`-подписями того же имени.
- **Без авторизации**, только домашняя сеть.

- **Отдельный образ:** sd-scripts проверен на Python 3.10 и PyTorch 2.6–2.8, у ComfyUI 3.13 и 2.14.

- **Проект задаёт, что обучать** (`training/<имя>.yaml`: база, шаги, ранг, learning rate, разрешение, повторы), **инструмент — как уместить в 10 ГБ** (только U-Net, кеши энкодеров и латентов, gradient checkpointing, bf16, AdamW8bit). Сменится машина — файлы проектов не меняются.
- **Подписи руками;** автоподписи отложены в ROADMAP.
- **Промежуточные сохранения в `loras/`, а не в `output/`:** ComfyUI видит LoRA только там, а без этого их не сравнить через `run.py`. `loras/` в `.gitignore`.

Первый раунд (шаг 200) прошёл, после второго (шаг 400) видеопамять дошла до 9,9 ГБ из 10, оперативная — до 12,4 из 15,5, и обучение встало: семь минут без единого шага. **Найдено:**

- **`torch.cuda.mem_get_info` под WSL не видит чужую видеопамять:** при работающем ComfyUI показывал 8,86 ГБ свободными, `nvidia-smi` — 2,75. Тренер проверяет через `nvidia-smi`, он есть в контейнере.
- **`accelerate config` при сборке образа выбирает CPU:** видеокарты при сборке нет. Первое обучение пошло на процессоре; теперь настройки передаются `accelerate launch` флагами при запуске.
- **PyTorch с `--index-url` индекса PyTorch не ставится:** зависимости нужен `flit_core` с PyPI. PyPI подключён дополнительным индексом, а PyTorch закреплён версией `+cu128`, которая есть только в индексе PyTorch.
- **Сборка образа во время генерации** упирается в 16 ГБ памяти WSL: одна картинка шла 12 минут вместо 13 секунд. Записано в README.

- **ROADMAP собран из планов Lootlords:** LoRA, спрайты по одному скелету, постобработка с `rembg`, иконки с рамкой, оверлеи по точкам крепления. Сначала доводим инструмент по этому списку, потом возвращаемся к играм и дополняем его по надобности. Всё проектное инструмент берёт из папки проекта.
- **База — SDXL.** Генерация и обучение LoRA помещаются в 10 ГБ, лицензия разрешает коммерческое использование. Flux на 10 ГБ только генерирует, и медленно, а FluxGym требует для LoRA минимум 12 ГБ.
- **ComfyUI в Docker, а не portable-сборка.** Smart App Control в Windows 11 блокирует неподписанные `.dll` и `.pyd` из Python-пакетов, portable-сборка не запустилась. Выключать защиту пользователь не захотел, а Linux внутри Docker она не трогает.
- **ComfyUI, а не A1111, Forge, InvokeAI или Fooocus.** Граф workflow отправляется по HTTP API в виде JSON, его можно хранить в git и прогонять пачкой; новые модели и техники появляются в ComfyUI раньше других. Для ручной доработки позже можно подключить Krita AI Diffusion к этому же серверу.
- **Версии закреплены:** ComfyUI на релизе старше недели, PyTorch по рекомендации README ComfyUI (CUDA 13.0 нужна для серий 20 и новее). Обновляем вместе.
- **Расширения в образ не ставим:** скелет позы готовим сами, препроцессоры OpenPose не нужны.
- **Docker Desktop — с docker.com, а не из Microsoft Store.** Ошибка `docker-credential-desktop: executable file not found` оказалась не про Store: в системном `PATH` была запись `C:\Program Files\WireGuard"` с лишней кавычкой, и Go на Windows сливал после неё все папки в одну. Рецепт — в README.

**Найдено при запуске:**

- **«Missing models» в шаблоне** было из-за трёх причин сразу: `.env` указывал на папку по умолчанию, контейнер не пересоздали после правки `.env`, а шаблон «SDXL Simple» ждёт ещё и refiner. В README — что проверить и что выбрать в узле.
- **WSL 2 отдаёт контейнерам половину RAM:** ComfyUI видит 15,9 ГБ из 32. Для генерации хватает; для обучения лимит поднимается через `.wslconfig`.
