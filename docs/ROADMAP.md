# Roadmap

Чеклист инструмента. Пункты отмечаем по ходу работы. Первый набор собран из планов Lootlords (концепт и ROADMAP игры): всё, что там относится к самому инструменту, а не к арту конкретной игры. Новые пункты добавляем, когда они понадобятся проектам.

Всё проектное — размеры, палитра, скелет позы, точки крепления, рамка иконок, куда класть файлы — инструмент берёт из папки проекта, а не держит у себя.

## Сейчас

- **Шаг:** между 1 и 2 — данные ComfyUI переезжают в `data/` репозитория
- **Ветка:** `chore/data-in-repo` — ждёт PR и мерджа в `main`
- **Дальше:** 2. Формат папки проекта

## Этапы

Порядок — по зависимостям: каждый шаг опирается на предыдущие.

- [x] **1. ComfyUI в Docker** на Windows-машине с RTX 3080: SDXL и ControlNet позы, папки по проектам, пробная генерация. Перенесено из ветки `feature/art-comfyui` репозитория Lootlords.
- [ ] **2. Формат папки проекта** в репозитории проекта (у Lootlords — `art/`). `project.yaml`: имя, базовая модель, версия LoRA, холст спрайта, палитра, скелет позы с точками крепления, размер и сетка иконок, контракт выгрузки (имена файлов и куда их класть). Рядом — промпты, скелеты поз, эталоны с подписями. Эталоны — через Git LFS, LoRA — в GitHub Releases репозитория проекта.
- [ ] **3. Клиент для Mac** в Docker: читает папку проекта, загружает входы в `input/<проект>/`, отправляет workflow на `http://<IP Windows>:8188`, забирает результаты из `output/<проект>/`.
- [ ] **4. Текст → картинка:** типовой workflow для кандидатов в эталоны и фонов.
- [ ] **5. Обучение LoRA** в Docker: выбрать тренер (kohya sd-scripts или OneTrainer), датасет из папки проекта (20–30 эталонов с подписями), результат в `models/loras/<проект>/`. Если не хватит памяти, поднять лимит WSL через `.wslconfig`.
- [ ] **6. Спрайт по скелету:** LoRA стиля + ControlNet позы по одному скелету проекта, чтобы все персонажи были в одной позе и пропорциях, с фиксированными точками крепления.
- [ ] **7. Постобработка и выгрузка:** удаление фона через `rembg`, квадратный прозрачный холст по размеру из проекта, персонаж во весь рост с ногами у нижнего края по центру, приведение к палитре проекта. Файлы выгружаются по контракту проекта: имя, размер, папка.
- [ ] **8. Иконки предметов и карт:** workflow с единым шаблоном рамки, размер и сетка — из проекта.
- [ ] **9. Оверлеи снаряжения:** предмет (оружие, шлем, плащ) генерируется в позе базового скелета и ложится на спрайт по точкам крепления. Позже — полная бумажная кукла без перерисовки базового спрайта.
