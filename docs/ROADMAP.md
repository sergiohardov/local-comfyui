# Roadmap

Чеклист инструмента. Пункты отмечаем по ходу работы. Первый набор собран из планов Lootlords (концепт и ROADMAP игры): всё, что там относится к самому инструменту, а не к арту конкретной игры. Новые пункты добавляем, когда они понадобятся проектам.

Инструмент — сервис на Windows: визуальный интерфейс ComfyUI и HTTP API на одном адресе. Проекты пользуются им с Mac как платным сервисом: всё проектное (референсы, промпты, размеры, палитра, скелет позы, куда класть файлы) живёт в репозитории проекта и приходит в запросах, а инструмент хранит только базовые модели и библиотеку LoRA.

## Сейчас

- **Шаг:** 5–7. Инструмент как сервис
- **Ветка:** `feature/tool-api` — в работе
- **Дальше:** 8. Спрайт по скелету

## Этапы

Порядок — по зависимостям: каждый шаг опирается на предыдущие.

- [x] **1. ComfyUI в Docker** на Windows-машине с RTX 3080: SDXL и ControlNet позы, пробная генерация. Перенесено из ветки `feature/art-comfyui` репозитория Lootlords.
- [x] **2. Подключение проекта:** папка проекта через `PROJECT_DIR`, `project.yaml` с проверкой при старте, заготовка `template/`. Заменяется сервисом в шагах 5–7.
- [x] **3. Текст → картинка:** типовой граф `txt2img` в Browse Templates (свой пакет без узлов); пакетный прогон `run.py` по спискам из папки проекта — заменяется API в шаге 5.
- [x] **4. Обучение LoRA:** kohya sd-scripts в своём образе, настройки под 10 ГБ ставит инструмент; версии `<имя>-v<N>` и промежуточные сохранения для сравнения; шаблон `txt2img-lora`. Запуск из командной строки на Windows — заменяется API в шаге 6.
- [ ] **5. API генерации и библиотека LoRA:** пакет `local-comfyui` добавляет в ComfyUI `/tool/generate`, `/tool/jobs/{id}`, `/tool/status`, `/tool/loras` (список, загрузка, скачивание, удаление); цепочка из нескольких LoRA с весами; seed до 64 бит, как в интерфейсе.
- [ ] **6. Обучение через API:** `/tool/train` принимает zip с картинками и подписями и параметры; тренер — сервис во внутренней сети Docker; прогресс в `/tool/status`; на время обучения генерация отклоняется и в API, и в интерфейсе; LoRA с версиями ложится в библиотеку.
- [ ] **7. Без папки проекта:** убрать `PROJECT_DIR`, `project.yaml` и проверку при старте, `template/`, `run.py`; входы и черновики — в `data/`.
- [ ] **8. Спрайт по скелету:** LoRA стиля + ControlNet позы по скелету, который присылает проект, чтобы все персонажи были в одной позе и пропорциях, с фиксированными точками крепления.
- [ ] **9. Постобработка:** удаление фона через `rembg`, квадратный прозрачный холст, персонаж во весь рост с ногами у нижнего края по центру, приведение к палитре; размеры и палитра — в запросе.
- [ ] **10. Иконки предметов и карт:** граф с единым шаблоном рамки; рамка, размер и сетка — в запросе.
- [ ] **11. Оверлеи снаряжения:** предмет (оружие, шлем, плащ) генерируется в позе базового скелета и ложится на спрайт по точкам крепления. Позже — полная бумажная кукла без перерисовки базового спрайта.

## Отложено

- [ ] **Автоподписи эталонов:** черновик подписей моделью-теггером (BLIP или WD14) с правкой руками. Делаем, если писать подписи руками станет утомительно.
- [ ] **Доступ не из домашней сети:** токен для API; до тех пор — только домашняя сеть или VPN вроде Tailscale.
