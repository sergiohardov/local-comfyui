# Roadmap

Чеклист инструмента. Пункты отмечаем по ходу работы. Первый набор собран из планов Lootlords (концепт и ROADMAP игры): всё, что там относится к самому инструменту, а не к арту конкретной игры. Новые пункты добавляем, когда они понадобятся проектам.

Инструмент — сервис на Windows: визуальный интерфейс ComfyUI и HTTP API на одном адресе. Всё проектное (референсы, промпты, скелеты телосложений, куда класть файлы) живёт в репозитории проекта и приходит в запросах, а инструмент хранит только базовые модели и библиотеку LoRA. Персонаж — 2D в одном ракурсе, из частей на костях.

- [x] **10. Иконки предметов и карт:** `post` с типами `frame` и `icon`; рамка генерируется от заготовки-кольца, которую рисует инструмент (img2img, кубик `init`), окно вырезается по известному прямоугольнику; иконка — предмет вписан в окно, цвет окна и тонировка рамки по редкости. - [x] **12. Снаряжение по слотам:** `init` — сохранённая картинка базы, `slot` — зона, которую строит инструмент по скелету: `armor` (тело без головы, кистей и стоп), `helmet` (голова выше челюсти, поза без точек лица), `right_hand` / `left_hand` (зона у кулака, рука не перерисовывается). ## Шаг 15: сценарии — графы проекта

**Зачем.** Каждый новый вид ассета (спрайт, рамка, иконка, оверлей, части, слоты, перенос) добавлялся в инструмент кодом — методом или полем API; следующий (пиксель-арт со своей палитрой) потребовал бы ещё код. Пользователь: так не должно быть, инструмент — общий. Проверено 2026-10-30 (журнал, «арт Lootlords и сценарий-граф»): рынок в пиксель-арте получен одним `curl`-запросом к штатному API ComfyUI с графом из встроенных узлов — без кода в инструменте и без доступа к диску Windows, как запрос с Мака.

**Как будет устроено.**

- **Сценарий — граф ComfyUI в формате API** (JSON), который собирают мышкой в интерфейсе (Workflow → Export (API)) и хранят в репозитории проекта (у Lootlords — `art/workflows/`). Клиент подставляет свои значения (промпт, seed, LoRA, входные картинки) и отправляет граф штатным API ComfyUI на том же порту: `POST /upload/image` (входы), `POST /prompt`, `GET /history/{id}`, `GET /view`, `GET /object_info` (что есть). Новая задача — новый граф, без кода в инструменте.
- **Инструмент даёт то, чего нет в ComfyUI:** библиотеку LoRA (`/tool/loras`), обучение (`/tool/train`) с блокировкой видеокарты (middleware на `POST /prompt` — уже действует и для штатного API), статус (`/tool/status`), задания обучения (`/tool/jobs/{id}`).
- **Операции, которых нет среди встроенных узлов, — наши узлы** в пакете `local-comfyui` (`NODE_CLASS_MAPPINGS`), а не методы API: тогда они доступны в любом графе и в интерфейсе. Это свой пакет, не стороннее расширение; инвариант «сторонние расширения не ставим» остаётся.

**Что во что превращается** (код уже есть, переносится, а не пишется заново):

| Сейчас | Станет | Откуда код |
| --- | --- | --- |
| `pose` в `/tool/generate`, `POST /tool/pose` | узел «скелет по точкам»: JSON точек → картинка для ControlNet (с опцией «без точек лица» для шлема) | `pose.py` |

**Решения по открытым вопросам** (15.1, проверено на ComfyUI v0.42.1):

- **Файлы, не картинки** (`rig.json`, GIF): штатный `GET /view` отдаёт любой файл из `output` с типом по расширению — свой маршрут не нужен. Мелкие значения (окно рамки, предупреждения) узел кладёт в `/history` через `ui`.
- **Своего метода «запусти граф» нет:** хватает штатных `/upload/image`, `/prompt`, `/history`, `/view`. Блокировка видеокарты на время обучения уже стоит на `POST /prompt`.
- **Имена моделей и LoRA** в графе — как в библиотеке: `проект/имя.safetensors`. Неизвестное имя штатный `/prompt` отклоняет сразу: `400` и `node_errors` с полем. Список — `GET /tool/loras` или `GET /object_info/LoraLoader`.
- **Точки скелета и окна** — строки JSON в виджете: клиент подставляет их как текст, а в интерфейсе их видно и можно править. Свой тип входа не нужен. Ошибки входов узел отдаёт исключением с текстом — оно в `/history` (`execution_error`).

## Отложено

- [ ] **Плащ:** висит за телом и должен двигаться с плечами — отдельные части за туловищем, возможно на своих костях.
- [ ] **Открытые шлемы с видимым лицом:** в прототипе модель либо не рисовала шлем, либо меняла лицо.
- [ ] **3D и разные ракурсы:** TRELLIS.2 в ComfyUI работает на 10 ГБ и даёт одинаковую модель со всех сторон, но рисованную иллюстрацию из неё получить не удалось (журнал, «прототип 3D»). Персонаж — 2D в одном ракурсе. Вернуться, если игре понадобятся ракурсы; непроверенный путь — форма из 3D через ControlNet глубины или контура и LoRA стиля.
- [ ] **Автоподписи эталонов:** черновик подписей моделью-теггером (BLIP или WD14) с правкой руками. Делаем, если писать подписи руками станет утомительно.
- [ ] **Доступ не из домашней сети:** токен для API; до тех пор — только домашняя сеть или VPN вроде Tailscale.
